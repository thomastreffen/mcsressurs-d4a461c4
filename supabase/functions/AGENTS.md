- Tripletex calls run only in edge functions via a `tripletex_connections` row (per company+environment, secret by name, Tripletex company verified, mode off/read_only/write_enabled) and `_shared/tripletex-guard.ts`; links are trigger-checked against their connection. Why: no company's data can reach another company's Tripletex.
- Stable Tripletex IDs live in `tripletex_links` (environment + Tripletex company + internal Tripletex id; number/name only as snapshot); a pending row is reserved before any create and partial unique indexes block duplicates. Legacy `tripletex_project_mappings`/`external_tripletex_id` are left untouched until migration. Why: idempotent, environment-separated mapping that never confuses numbers with IDs.
- Tripletex employee links key on canonical `people.id` (mcs_entity_type='employee'), resolved from a resource-plan assignee via `technicians.user_id -> user_accounts.auth_user_id (unique) -> person_id` in `resolveAssigneeIdentity`; a shared technician/people UUID is never trusted alone, names/e-mail never; unresolved -> `employee_identity_unresolved`, no network. Participant writes resolve job -> financial project (self or `parent_project_id`). Why: technicians.id differs from people.id for some staff.
