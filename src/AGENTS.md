Why: preserve scope and prevent duplicate or unintended permissions.

- Mine unions project_members via auth-user accounts, technician user_id bookings, task assignments and canonical person-based planning responsibility over RLS-visible IDs, inheriting only within company. Why: relevance is not authorization or a new membership model.
- Large Sheets opt in with mobileWorkspace for dvh/full-width/safe-area; preserve confirmations and desktop widths. Why: avoid blanket dialog regressions.
- Personal incident history groups existing visible rows with presentation-only helpers; desktop filters and incident workflows remain independent. - Documentation requirements: per-company matrix (doc_* tables, migration 0082) snapshotted onto jobs via RPC; job classification lives in doc_job_profiles, never on events. Why: no retroactive rules and no events-trigger side effects.
- Resource Plan Outlook status per person comes only from resource_plan_outlook_sync_status (reuses resource_plan_personnel company scope); schedule_sync_state stays service-role only. Why: no cross-company leakage of sync errors.
- Order messages: composer rules live in src/lib/order-message-rules.ts; internal notes can never address customers, status e-mail policy is mandatory/default-on per status with an optional combined message (never forced free text), customer-facing status wording comes only from supabase/functions/_shared/order-customer-status.ts (tracking page + e-mail), and email_notification_sent is set server-side (order-form-notify) only after Graph acceptance with per-message/event dedupe. Auto status resolution counts only genuine customer replies after the status change. Why: no hidden notes, false receipts or instant status reverts.
- Order → Resource Plan task with several workdays creates ONE event (one order link, one approval/calendar flow) plus schedule_blocks per technician × chosen date via src/lib/order-task-dates.ts; specific dates, never weekly recurrence. Why: no duplicate jobs or customer orders.
- Multi-day jobs sync to Outlook as ONE event per (job, technician, workday): pure plan/diff in _shared/multi-day-calendar.ts, orchestration with injected store/graph in _shared/multi-day-sync.ts, mapping in job_calendar_day_links with deterministic idempotency key calday:{event}:{tech}:{date}; legacy single-event path stays for jobs without schedule blocks, and a legacy day-1 event is adopted into its day link instead of duplicated. Approval/info e-mails list all planned days (formatPlannedDays). event_recipient_delivery keeps ONE calendar summary row per technician (aggregateTechDayDelivery: sent only when every day is synced); update_only never creates days – missing days are created only by the explicit create_missing_days action (create-only, no PATCH/DELETE, no e-mail; its receipt says "Opprettet" only for per-day outcome=created, i.e. a Graph POST in that run). Why: "sto ikke i kalenderen min" – day 2+ must reach Outlook, with no duplicates on retry.
- Availability conflict checks (ms-calendar "availability") take job_id, exclude the job's OWN Outlook copies per technician via _shared/availability-filter.ts (exact start/end match within 2 min against schedule_blocks, day links and legacy links), span all planned days, and render slots via formatSlotOslo (Graph designator-less dateTime is UTC, always shown in Europe/Oslo with date). Why: the job's own copy must never appear as a conflict, and UTC must never render as local time.
